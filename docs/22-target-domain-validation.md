# 22 · 目标域真实数据验证（首次）

> 数据：用户于 2026-11-08 用现有 iOS App 采集，972 帧，419 MB。
> 本文全部数字来自实际运行，无估算。

## 2. 深度质量（实测）

| 指标 | 值 |
|---|---|
| 有效像素 | 100% |
| 工作距离中位 | 0.393 m |
| 平面拟合 σ | **中位 1.42 mm，P95 1.65 mm** |
| 平面内点率 | **中位 91%** |
| 拟合失败 | 0 / 972 |

木桌是极好的平面，σ 比此前在室内墙面测得的 2.0 mm 还低。
**这直接证明"高出 8 mm"在该距离下是 5.6σ 信号。**

## 3. 边框误报（已修复）

初版在 972 帧上**每帧都检出 ≥2 个障碍**。可视化后发现：

- 画面左边缘有 3 条 8–9 mm 的竖条；
- 右上角有一大块 11 mm 的区域，实际是纯桌面。

根因：深度传感器在画面边缘存在系统偏差与无效点。
修复：**丢弃触及边框 6 px 内的连通域**（`DEFAULT_BORDER_MARGIN_PX`）。

修复后分布变为：

| 检出数 | 帧数 | 占比 |
|---|---|---|
| 0 个 | 430 | 44% |
| 1 个 | 511 | 53% |
| 2+ 个 | 31 | 3% |

## 5. 端到端结果（972 帧）

采用 `road_source=plane`（可通行区 = 平整地面）+ `obstacle_mode=geometric`：

| 风险等级 | 帧数 | 占比 |
|---|---|---|
| **SAFE** | 430 | 44% |
| **MEDIUM** | 542 | 56% |
| UNKNOWN | 0 | 0% |

剩余通行宽度：min **0.150 m**，中位 **0.242 m**，max 0.479 m。

> UNKNOWN 为 0 说明：只要平面拟合成功、深度有效、可通行区完整，
> 系统就能给出结论——这正是 fail-closed 之外的"可判定"路径。

## 6. 这次验证证明了什么 / 没证明什么

### 证明了

1. **几何障碍检测在真实 LiDAR 数据上可用**：σ 1.42 mm，8 mm 即 5.6σ；
2. **全链路能产出结论**：道路/可通行区 → 障碍 → 侵入 → 米制剩余宽度 → C++ 引擎 → SAFE/MEDIUM；
3. **边框抑制有效**：误报从"每帧都有"降到 3%。

### 没有证明

1. **没有标注，因此没有正式的 precision/recall**——只有 4 个目标的人工抽查；
2. **场景重复度高**：每个场景约 20 帧，972 帧实际约 50 个独立场景；
3. **只看得到 ≥8 mm 的凸起**：薄片、平躺的石头、透明物体会漏检；
4. **可通行区是"平整桌面"而不是"道路"**：`road_source=plane` 只适用于固定俯视的
   沙盘/桌面，**不能用于真实道路**（那会把人行道、路肩也算成可通行）；
5. **贴边物体被抑制**：画面边缘 6 px 内的真实物体不会被报出（如边缘的手）。

## 8. 结论

**系统第一次在真实采集数据上给出了非 UNKNOWN 的判定**：
桌面平整→SAFE，有物体凸起→MEDIUM/RESTRICTED 并给出米制剩余宽度。

但这只是"链路可用"的证据，**不是"能判断山区公路落石"的证据**。
两者的差距需要沙盘数据与标注来填。

## 9. 沙盘尺度确认与策略标定（用户 2026-11-08 确认）

### 9.1 尺度

| 项 | 值 |
|---|---|
| 单车道宽 | **4 cm** |
| 双向总宽 | **8 cm** |
| 沙盘是否放小车 | **不放** |
| 小颗粒（3–5 mm）是否要测 | **不测**（与传感器分辨率一致，见 §3.1） |

### 9.2 策略语义调整

沙盘没有小车，因此 `vehicle_width_m` **不再表示车宽，而表示单车道宽度**。
判据变为：**剩余宽度不足一个车道（4 cm）即视为该方向不可通行。**

新增 `risk_engine/policy/sandbox_4cm_lane.json`：

```json
{"vehicle_width_m": 0.040, "safety_margin_m": 0.0, "min_pass_width_m": 0.040,
 "alternative_margin_m": 0.005, "required_lookahead_m": 0.15, "policy_version": 2}
```

**不需要改 C++ 默认值，也不影响 46 项 C++ 测试**——引擎原本就支持 `--policy`。

### 9.3 效果验证

构造"剩余 5 cm"的场景：

| 策略 | 结果 |
|---|---|
| 默认（7 cm 阈值） | HIGH / BLOCKED |
| 沙盘（4 cm 阈值） | **MEDIUM / RESTRICTED** |

一个 8 cm 的双向路，落石后还剩 5 cm，单车道仍可通过——判 RESTRICTED 才合理。

### 9.4 已接入运行链路

`ROAD_RISK_POLICY` 默认指向该文件，后端拉起引擎时自动传入。
已核实运行中的进程参数：

```
rock_risk_cli --stream --policy .../sandbox_4cm_lane.json
```

### 9.5 仍未解决

1. **`road_source=plane` 在沙盘上不成立**：它把整片平整地面当可通行区，
   沙盘里道路 4 cm、两侧也是平的，会被当成整张桌子都可通行。
   沙盘上必须用道路分割（U-Net 微调）把 4 cm 道路分离出来。
2. 3–5 mm 颗粒不可见（物理限制）。
