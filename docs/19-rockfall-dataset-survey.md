# 19 · 落石检测数据集调研（P0）

> 调研日期：2026-11-07。原则：**不凭名称判断**，能下载的必须看到真实图像与标注；
> 无法访问或没有许可的，一律不得声称"已获得"。

---

## 1. 结论

**没有找到同时满足"真实山区公路场景 + 可用标注 + 明确许可 + 可下载"的落石检测数据集。**

现有名为 "rockfall" 的公开数据几乎全部落在两类**与本项目无关的域**：

1. **行星探测**（火星/月球巨石）——外观、光照、背景、尺度全不同；
2. **地震学 / GIS 地质调查**——不是图像检测数据。

唯一找到的"真 YOLO 格式"落石数据集是**露天矿**画面，且无许可证、近半数标注为空。

### 3.1 关键证据：那个"真 YOLO 数据集"到底长什么样

抽样查看 `frame_0000_*.jpg`：

- 画面是**露天矿**：黄色矿用自卸卡车 + 破碎岩壁，非山区公路；
- 标签 `frame_0000_*.txt` **为空文件**；
- 随机抽 25 个标签：**12 个为空（48%）**，共 23 个框，只有 1 个类别（id=0）。

结论：不能用于训练，更不能作为落石检测能力的证明。

## 4. 为什么找不到

三个结构性原因：

1. **落石是低频事件**，公开标注成本高，学术界多用自己的私有数据；
2. **"rockfall" 一词被行星探测与地震监测占据**，检索被大量无关结果淹没；
3. **社区数据集（Roboflow）许可碎片化**，且多数是从未署名的二次转载——
   本次找到的那个矿场数据集文件名带 `.rf.` 前缀（Roboflow 导出格式），
   本身就是二次转载，无法追溯原始授权。

## 5. 推荐路径（需要你选）

### 路径 A：自采真实帧（推荐）

用 iPhone（现有采集端）拍 **100–200 帧**真实场景，人工标注。

| 优点 | 缺点 |
|---|---|
| 域完全匹配（就是我们要判的场景） | 需要人工拍摄与标注 |
| 许可完全自控 | 数量有限 |
| 可直接复用现有 iOS 上传链路 | |

> 桌面摆几块石头、从 0.64 m 俯拍，**就是沙盘域**（只差背景道路）；
> 有条件再去真实山路拍一段。

### 路径 B：合成预训练（过渡）

用 AeroScapes 道路场景 + 有明确许可的岩石图像合成检测样本。

| 优点 | 缺点 |
|---|---|
| 立刻能跑通训练与评估链路 | **合成数据，必须标注 SYNTHETIC** |
| 可控地生成遮挡/多石/边缘等场景 | 真实感有限，不能替代目标域验证 |

### 路径 C：补充检索（需你提供条件）

- Roboflow：需要你的 API key（`api.roboflow.com` 已确认可达，仅缺凭据）
- HuggingFace：等网络恢复后补检

---

## 6. 明确不做的事

1. 不使用火星/月球数据训练"地球落石检测"；
2. 不使用无许可证的仓库数据（当前找到的都不合规）；
3. 不把 AeroScapes 的 `Obstacle` 类当作 `Rockfall`；
4. 不因为"训练出 mAP"就宣称具备落石检测能力——还需 §7 的分层评估。

---

## 7. 检测能力 ≠ 业务能力（评估分层）

| 层次 | 含义 | 当前状态 |
|---|---|---|
| A | 能否框出岩石目标 | 无模型 |
| B | 能否判断落石与道路的空间关系 | 引擎已有侵入逻辑，但无落石输入 |
| C | 能否判断是否侵入可通行空间 | 同上 |
| D | 能否给出通行风险 | 依赖 A–C |

四层必须分开汇报，不得用 A 的 mAP 代替 D 的结论。
